# 汐眠（TideSleep）——调研结果与实施方案

> 版本：v0.1｜日期：2026-09-19  
> 核心参考：[领研网｜MIT 粉红噪声增强脑脊液清除](https://www.linkresearcher.com/theses/ee8440be-cf29-4840-9c95-c126328de734)  
> 原论文：Levitt & Lewis et al., *Closed-loop auditory stimulation in phase with slow waves during sleep enhances cerebrospinal fluid flow in humans*, *Science Translational Medicine* (2026), DOI: 10.1126/scitranslmed.aea5469

---

## 1. 产品命名

| 项 | 内容 |
|---|---|
| **中文名** | **汐眠** |
| **英文名** | TideSleep |
| **寓意** | 「汐」对应睡眠中脑脊液（CSF）的潮汐式波动；「眠」点明助眠场景。产品主张：在入睡后、以正确时机的轻柔粉红噪声脉冲，强化慢波与脑内「清理潮汐」。 |
| **口号（可选）** | 等你睡着，再推一把慢波 |
| **备选名** | 眠汐、清汐、慢波眠、粉汐 |

**为何不用「白噪音助眠」类名字：** 本产品的科学锚点不是「整夜播放背景声」，而是 **闭环、相位锁定、短脉冲**；命名需与市面白噪音 App 拉开差异。

## 2. 调研结果

### 2.1 锚点论文（你给的 LinkResearcher / MIT）

**做了什么**

- 白天大脑产生乳酸、老化蛋白等废物；夜间睡眠时，脑脊液（CSF）波动帮助冲刷废物。
- MIT 团队证明：在睡眠中，于 **慢波（slow wave）峰值时机** 播放 **约 50 ms 的粉红噪声（pink noise）短脉冲**，可 **增大慢电波振幅**，进而 **增强 CSF 波动幅度**。
- 机制链条：听觉脉冲 → 强化慢波 → 血管舒缩泵作用增强 → CSF 进出脑的潮汐加强 →（潜在）废物清除增强。
- 技术难点：要在慢波峰值「推一把」；他们用 EEG 实时测慢波，并用算法预测峰值以补偿延迟（MRI 干扰 EEG 时尤其关键）。刺激音量 **不足以吵醒人**。
- 样本：14 名健康志愿者；结果主要是 **生理信号增强**（慢波 + CSF），**尚未**在临床层面证明改善失眠评分、认知或延缓阿尔茨海默病。
- 商业侧：第一作者等已创办相关公司（如 Cerebloom），方向是 **头戴式 EEG + 正确时机播音** 的家用设备；有专利披露。

**对产品的硬约束（必须写进方案）**

1. **不是「睡着后一直放粉红噪声」**。论文与后续报道强调：效果依赖 **相位对齐**；非 REM 时随便播，未必有同样 CSF 增强。
2. **手机喇叭 alone 无法做真闭环**：缺少头皮/前额 EEG，无法检测慢波峰值。
3. **安全第一**：过响、过密、错误阶段的声音会碎片化睡眠（已有开放环/破坏性刺激研究显示：即使短暂拉高 delta，频繁觉醒会损害次日警觉）。

### 2.2 相关领域补充调研

| 方向 | 结论 | 对本 App 的含义 |
|---|---|---|
| **闭环听觉刺激 CLAS / PLAS**（Ngo 2013 等） | 在慢波 up-state 播放粉红噪声脉冲，可增强慢振荡、纺锤波耦合，部分研究改善陈述性记忆巩固 | 金标准是 **EEG 闭环**；家庭版需头环或贴片 |
| **非相位锁定粉红噪声**（如 DovePress/NSS 2020） | 在 NREM 中由技师监督播放，可提高 N3 比例；但「破坏性」环境音虽也能瞬间抬高 delta，却增加觉醒、损害次日表现 | MVP 若无 EEG，只能做 **低音量、稀疏脉冲、仅深度睡眠窗口** 的开放环近似，并明确「非论文级闭环」 |
| **失眠患者家用闭环**（近年试点） | 可增强慢波相关频段；睡眠效率/主观量表改善 **不一致** | 对外话术应是「强化深度睡眠相关生理过程」，避免「治疗失眠/防痴呆」未经批准的医疗宣称 |
| **整夜连续噪声** | 部分证据提示可能压缩 REM 等 | **默认禁止整夜连续播放**；会话应有时长上限与出睡即停 |

### 2.3 竞品与形态对照

| 形态 | 代表思路 | 与汐眠关系 |
|---|---|---|
| 白噪音 / 助眠 App | 睡前或整夜连续播放 | 差异化：我们主打 **入睡后、脉冲式、可联动穿戴** |
| 消费级 EEG 头环 + 声音 | Elemind / Dreem / 论文衍生头环 | 汐眠 **P2 目标形态**；P0/P1 用手机+音箱+手表先验证场景 |
| 小爱音箱助眠 / 定时白噪音 | 定时或语音触发 | 可复用为 **播放器**，但触发应来自「已入睡」而非固定时钟 |

### 2.4 米家 / 小米穿戴能力调研（可落地）

**A. 米家自动化（用户侧最快通路）**

- 支持穿戴（如小米手环 10 及后续、Xiaomi Watch S3/Watch 5 等，以米家实际展示为准）作为自动化 **触发/状态条件**。
- 设备侧常见属性：`sleep-state`：**0 = 睡着，1 = 醒来**。
- 前置条件（摘要）：
  - 米家 App 较新版本（如 10.0+）；
  - 穿戴绑定 **小米运动健康**；
  - 米家「人车家数据访问管理」打开运动健康数据访问；
  - 穿戴出现在米家设备列表；
  - 上报通道：搭载 **HyperOS 2+** 的小米手机，和/或 **蓝牙 Mesh 网关**（部分小爱音箱型号不支持作网关）。
- 典型场景：`若 手环/手表 睡眠状态 = 睡着` → `则 小爱音箱 播放指定内容 / 执行场景`；`若 醒来` → `停止播放 / 降低音量`。

**B. 小米穿戴第三方 App 开放能力（App 内开发通路）**

- 文档：《小米穿戴第三方 APP 能力开放接口文档》v1.4。
- 需 `Permission.DEVICE_MANAGER`。
- 可 **查询 / 订阅** 睡眠状态：
  - 状态值：睡眠中 / 清醒；
  - 事件：入睡 / 出睡。
- 适合安卓端自有 App 直接订阅，比「只靠米家场景」更可控（延迟、日志、与本地播放器同步）。

**C. 能力边界（诚实写清）**

| 能做到 | 做不到（当前消费级穿戴） |
|---|---|
| 检测大致「已入睡 / 已醒来」 | 检测慢波相位、N2/N3 精确分期到毫秒级 |
| 触发「开始/停止播音」 | 替代 EEG 做论文级闭环 |
| 联动小爱音箱、台灯、空调等米家设备 | 保证所有机型/系统版本都有相同自动化项 |

## 3. 产品定位与原则

**一句话定位**  
汐眠是一款「**确认入睡后再播放**」的睡眠音频助手：用米家手表/手环判断入睡与出睡，在安全音量下以 **粉红噪声短脉冲（及可扩展音景）** 通过手机或小爱音箱播放；远期接入 EEG 头环，逼近 MIT 闭环方案。

**设计原则**

1. **先安全、再效果**：宁可不播，也不吵醒。
2. **科学诚实**：P0/P1 标注为「开放环 / 入睡触发」；仅当接入 EEG 才称「闭环相位刺激」。
3. **出睡即停、可一键静音、有单晚时长上限**。
4. **隐私**：睡眠状态默认本地处理；云同步需明示授权。

## 4. 实施方案

### 4.1 总体架构

```
┌─────────────┐     入睡/出睡事件      ┌──────────────────┐
│ 小米手表/手环 │ ───────────────────► │ 汐眠 App（手机）  │
│ + 运动健康   │   Wear SDK / 米家    │  会话引擎+音频引擎 │
└─────────────┘                       └────────┬─────────┘
                                               │
                    ┌──────────────────────────┼──────────────────────────┐
                    ▼                          ▼                          ▼
             手机扬声器/蓝牙耳机          小爱音箱（米家）            （P2）EEG 头环
             本地粉红噪声脉冲            播放/停止场景                相位锁定触发
```

**会话状态机（核心）**

`Idle → Arming（用户就寝开启）→ WaitingSleep → Stimulating → Paused/Stopped → MorningReport`

- `WaitingSleep`：仅监听入睡，不播。
- `Stimulating`：稀疏粉红噪声脉冲；检测出睡或超时 → 停止。
- 可选：入睡后延迟 N 分钟再开始（避开入睡潜伏期被声音干扰）。

### 4.2 分阶段路线图

#### Phase 0｜验证（2–4 周）——「入睡才播」

**目标**：跑通米家链路与安全播音，不做医疗宣称。

**交付**

- 安卓优先 App（或先用「米家自动化 + 小爱」无代码验证）。
- 配置页：目标设备、入睡延迟、音量上限（建议 ≤ 40–45 dB 量级，以主观「几乎听不到」校准）、单晚最长刺激时长（如 90–120 分钟）、脉冲参数（默认 50 ms 粉红噪声，间隔可调，如 2–8 s 随机抖动的开放环）。
- 日志：入睡时刻、开始播、停止原因（出睡/超时/手动）。

**米家无代码验证步骤（今天就能测）**

1. 手环/手表绑「小米运动健康」→ 米家开启数据访问 → 设备出现在米家。
2. 自动化：若「睡眠状态=睡着」→ 小爱播放白噪音/自定义；若「醒来」→ 停止。
3. 记录延迟（穿戴判睡往往滞后真实入睡数分钟到十几分钟——方案里要按这个延迟设计「延迟再播」）。

#### Phase 1｜产品化 MVP（6–10 周）——手机 App + 穿戴订阅

**平台**：Flutter 或原生（安卓优先，因 Wear SDK；iOS 以米家场景/Shortcuts 为辅）。

**模块**

| 模块 | 内容 |
|---|---|
| 设备层 | 小米穿戴：订阅 `睡眠状态`；可选 Health Connect / 小米运动健康导出作次日报告 |
| 音频层 | 本地生成/缓存 1/f 粉红噪声；50 ms 脉冲；淡入；AAudio/Oboe 低延迟；后台保活与勿扰兼容 |
| 会话层 | 状态机、安全策略、紧急停止 |
| 米家层 | 深链/文档引导用户配置自动化；进阶：用小米开放平台/IoT 能力控制音箱（视开放政策） |
| 数据层 | 本地 SQLite；可选同步 |
| 合规层 | 免责声明、非医疗器械标注、音量警告 |

**音频协议（开放环默认参数，可 A/B）**

- 刺激类型：粉红噪声脉冲，时长 **50 ms**（对齐论文）。
- 播放窗口：确认入睡后 **延迟 10–30 min**（可配）→ 持续最多 **首 2 个睡眠周期量级（约 90–120 min）**。
- 间隔：开放环可用伪随机（如 3–7 s），避免节律性惊醒；**禁止**默认整夜连续粉红噪声。
- 出睡：立即静音并结束会话。

**成功指标（MVP）**

- 入睡→开播端到端成功率 ≥ 90%（在支持机型上）。
- 用户报告「被吵醒」率 < 5%。
- 次日主观恢复感、可穿戴深睡占比（仅作探索性指标，不作疗效承诺）。

#### Phase 2｜科学闭环（3–6 月+）——EEG 配件

**目标**：逼近 MIT「预测慢波峰值 → 50 ms 粉红噪声」链路。

- 硬件：前额干电极头环 / 合作现成 EEG 消费硬件；蓝牙传实时 EEG 到手机或边侧芯片。
- 算法：慢波检测（0.5–1 Hz）+ 峰值预测；仅在 NREM/稳定慢波段刺激；运动伪迹则暂停。
- 输出：仍可走手机喇叭或床头音箱；延迟预算需严格标定（刺激必须落在 up-state 窗口）。
- 研究：小样本家庭试验；与大学/睡眠中心合作；再考虑医疗器械路径。

#### Phase 3｜生态与个性化

- 多用户家庭、访客模式。
- 与米家：关灯、调温、勿扰、清晨灯光。
- 个性化：根据可穿戴深睡/主观评分调节脉冲密度（仍保留安全上限）。
- 内容扩展：雨声等仅作「入睡辅助轨」；**深度刺激轨**与助眠氛围轨分离。

### 4.4 米家互动详细设计

**路径 1：用户配置米家自动化（最快）**

- App 内「一页说明书」+ 截图引导。
- 触发：穿戴「睡着」；执行：通知汐眠（Android Intent / 推送）或直接控音箱。
- 限制：延迟与稳定性依赖小米上报链路；App 需做「迟到入睡事件」的幂等处理。

**路径 2：App 直接订阅穿戴（推荐 MVP）**

- `NodeApi.subscribe(nodeId, 睡眠 DataItem, listener)`。
- 收到「入睡」→ 进入 WaitingSleep 延迟定时器 → Stimulating。
- 收到「出睡」→ 立即 stop。
- 同时可 query 佩戴状态：未佩戴则不进入刺激。

**路径 3：音箱作为扬声器**

- 短期：米家「播放白噪音/指定电台」动作；或手机投播到蓝牙音箱。
- 中期：若开放平台允许，云端/本地 IoT 下发播放自定义短音频（粉红噪声脉冲文件）。
- 注意：部分小爱型号 **不能** 当 Mesh 网关，穿戴上报需另配网关或 HyperOS 手机。

### 4.6 风险与合规

| 风险 | 对策 |

## 5. 结论与建议下一步

1. **正式定名：汐眠（TideSleep）**。  
2. **科学内核**已对齐 MIT/领研网文章：闭环粉红噪声短脉冲强化慢波与 CSF；产品必须分阶段，避免「整夜喇叭放粉红噪声」的错误落地。  
3. **最近一周最有价值的动作**：用你现有的小米手表/手环 + 米家自动化，验证「睡着→音箱出声→醒来停止」的延迟与误触发；同时做 50 ms 粉红噪声脉冲播放器原型。  
4. **MVP 应卖的是「可靠的入睡后触发 + 安全脉冲」**；「论文级清脑」留给 EEG 配件阶段。
